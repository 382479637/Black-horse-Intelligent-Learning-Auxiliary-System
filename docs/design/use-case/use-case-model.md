## 1. Actor 与系统边界

### 1.1 Actor

| Actor | 类型 | 说明 |
|---|---|---|
| 管理员（Administrator） | 主要 actor | 维护组织、人员、课程、班级、教学任务、学生与成绩；查看全局统计与预警 |
| 教师（Teacher） | 主要 actor | 查看本人任课班级与学生；维护本人任课 ClassCourse 的成绩；查看本人范围内的统计与预警 |

**不作为系统 actor：**

- 课程评审者、项目开发者：属于利益相关者，不操作系统。
- 学生：本版本不设学生登录端。
- 数据库/文件系统：属于系统内部实现，不画成 actor。

### 1.2 系统边界

```text
┌──────────────────────────────────────────────┐
│  黑马智能学习辅助系统                        │
│                                              │
│  登录/账户  基础数据  教学管理  成绩管理     │
│  统计分析  学习预警                          │
│                                              │
└──────────────────────────────────────────────┘
        ▲                              ▲
        │                              │
   管理员                          教师
```

- 系统边界内是用例，边界外是 actor。
- 系统启动、数据加载、初始化、CSV 保存属于基础设施行为，不作为 actor 用例；它们由 `ApplicationBootstrap` / `DataLoader` / `DataInitializer` 完成，验收见 AC-39、AC-40、AC-49、AC-50。
- 登录是执行大多数用例的前置条件，不画成所有用例的 `<<include>>`；否则会把前置条件误表达为公共子用例。

### 2.2 关系说明

- `UC-04a`、`UC-05a`、`UC-07a`、`UC-10a` 是对应用例的可选扩展，使用 `<<extend>>`：扩展用例只在用户选择该功能时执行；未实现 Should 项时，入口不显示。
- `UC-09a` 学生转班是管理学生中的独立目标，使用 `<<extend>>` 指向 `UC-09`；转班不是每次管理学生都必然发生。
- `UC-06a` 查看课程目录是独立用例，不是 `UC-06` 的扩展：教师只能查看课程目录，不能增删改；管理员的课程管理流程仍由 `UC-06` 承担。两者共享课程数据，但目标与权限不同。
- “管理部门”“管理员工”“管理课程”“管理班级”“管理教学任务”“管理学生”“管理成绩”是聚合型用例，包含查看、新增、修改、删除及相应异常流程；报告叙述时应展开，不能理解成单个按钮。
- 本图不使用 `<<include>>`：系统没有“每次执行某用例都必然发生”的独立用户子目标。登录是前置条件，班级/课程选择是界面步骤，统计计算是系统内部行为，均不应画成 include 用例。
- 不使用 actor 泛化：管理员和教师直接连接各自可执行的用例，避免引入一个需求中不存在的 `User` 角色。

## 3. 关键用例叙述

### UC-01 登录 / Login

| 项目 | 内容 |
|---|---|
| 主要 actor | 管理员、教师 |
| 前置条件 | 系统已启动并完成数据加载 |
| 后置条件 | 成功时进入对应角色主菜单；失败时停留在登录界面 |

**主流程：**

1. 系统显示登录界面，提示输入用户名和密码。
2. 用户输入用户名、密码。
3. 系统按用户名查找员工。
4. 系统验证密码哈希。
5. 系统检查员工状态为 `ACTIVE`。
6. 系统建立会话，按角色生成主菜单。

**异常流程：**

- 用户名不存在或密码错误 → 统一提示“用户名或密码错误”，不泄露账号是否存在。
- 密码正确但账号 `DISABLED` → 提示“账号已被禁用，请联系管理员”。
- 用户输入 `Q` → 安全退出。
- 输入 EOF → 安全退出。

### UC-06a 查看课程目录 / View Course Catalog

| 项目 | 内容 |
|---|---|
| 主要 actor | 管理员、教师 |
| 前置条件 | 已登录 |
| 后置条件 | 只读显示课程目录；不修改任何课程数据 |

**主流程：**

1. 用户进入课程目录。
2. 系统列出课程编号、名称、说明。
3. 用户可查看课程详情；管理员还可从该入口转入 `UC-06` 管理课程。

**异常流程：**

- 教师尝试新增、修改或删除课程 → 系统拒绝；菜单只提供查看入口，service 仍执行权限校验。
- 课程目录为空 → 显示空列表，不视为错误。

### UC-07 管理班级 / Manage Classes

| 项目 | 内容 |
|---|---|
| 主要 actor | 管理员 |
| 前置条件 | 已登录为管理员 |
| 后置条件 | 班级数据按操作更新；状态与引用规则保持有效 |

**主流程：**

1. 管理员查看班级列表。
2. 管理员选择新增、修改、指定/更换班主任、转换状态或删除。
3. 系统校验编号唯一、容量、日期、班主任资格和状态转换。
4. 系统保存变更并显示结果。

**异常流程：**

- 班级编号重复 → 拒绝。
- 容量低于当前在班人数 → 拒绝。
- 班主任不是 `ACTIVE` 的 `TEACHER` → 拒绝。
- 非法状态转换（如 `FINISHED → ACTIVE`、`PLANNED → FINISHED`）→ 拒绝并说明原因。
- 删除仍有学生或已有成绩的班级 → 拒绝。
- 删除 `FINISHED` 班级 → 一律拒绝。

### UC-09a 学生转班 / Transfer Student

| 项目 | 内容 |
|---|---|
| 主要 actor | 管理员 |
| 前置条件 | 已登录为管理员；学生存在 |
| 后置条件 | 学生 `classId` 更新；历史成绩仍绑定原 `classCourseId` |

**主流程：**

1. 管理员选择学生和目标班级。
2. 系统检查学生状态为 `ACTIVE`。
3. 系统检查当前班级不是 `FINISHED`。
4. 系统检查目标班级存在、状态为 `PLANNED` 或 `ACTIVE`、未满。
5. 系统更新学生班级。
6. 系统提示转班成功，并说明历史成绩仍归原班级。

**异常流程：**

- 学生为 `SUSPENDED` / `GRADUATED` → 拒绝，要求先恢复 `ACTIVE`。
- 当前班级为 `FINISHED` → 拒绝。
- 目标班级为 `FINISHED`、不存在或已满 → 拒绝。
- 目标班级日期已过但状态仍为 `PLANNED` → 允许，因为日期只用于展示。

### UC-10 管理成绩 / Manage Scores

| 项目 | 内容 |
|---|---|
| 主要 actor | 管理员、教师 |
| 前置条件 | 已登录；至少存在一个班级和已配置的 ClassCourse |
| 后置条件 | 成绩新增、更新或删除；统计与预警即时反映 |

**主流程：**

1. 用户选择班级。
2. 用户选择该班级的 ClassCourse（课程 + 任课教师）。
3. 系统列出该 ClassCourse 的学生与已有成绩。
4. 用户选择录入/修改或删除成绩。
5. 系统校验权限、学生班级、教师分配、班级状态和分数范围。
6. 系统保存成绩并显示结果。

**异常流程：**

- 教师选择非本人任课的 ClassCourse → 拒绝。
- ClassCourse 为“待分配” → 仅管理员可处理；新成绩录入被拒绝。
- 班级为 `PLANNED` → 新成绩录入被拒绝；已有成绩更正按 FR-SCORE-03 处理。
- 学生当前不属于该班级（新录入）→ 拒绝；已有成绩的修改/删除不受当前班级限制。
- 分数不在 `[0, 100]` → 拒绝；0 分是合法成绩。
- 同一学生同一课程已有成绩 → 更新原记录，不新增重复行；课程由 `ClassCourse.courseId` 解析，唯一键是 `(studentId, courseId)`，不是 `(studentId, classCourseId)`。
- 已有成绩属于其他 ClassCourse（学生转班后同课程）→ 不建立新成绩；当前用户能访问原 ClassCourse 时更新原记录，否则提示由原班级任课教师维护。

### UC-13 查看学习预警 / View Learning Warnings

| 项目 | 内容 |
|---|---|
| 主要 actor | 管理员、教师 |
| 前置条件 | 已登录 |
| 后置条件 | 显示每个学生的等级与命中规则；不持久化预警结果 |

**主流程：**

1. 用户选择班级。
2. 系统按当前用户的可见范围收集成绩：管理员取全部；教师只取本人任课 ClassCourse。
3. 系统对每名学生评估 R1–R6，收集所有命中规则。
4. 系统取最高等级，显示等级与全部命中规则。
5. 系统显示班级预警：及格率 < 60% 或平均分 < 60 → “需关注”。

**异常流程：**

- 可见范围内无成绩 → 显示“数据不足”，不参与等级比较。
- 教师可见范围内无该生成绩、但管理员可见范围内有 → 教师显示“数据不足”，管理员显示实际等级。
- 没有任何规则命中且有成绩 → “正常”。

## 6. 冻结时的设计取舍

1. **教师“我的班级”与“班级统计”的边界**：UC-14 只列出本人任课 `ClassCourse` 涉及的班级；班主任身份只展示，不额外授予权限。
2. **管理员“查看本人资料”**：不设独立入口；管理员通过员工管理查看本人资料。
3. **UC-09a 的归属**：保留 `<<extend>>` 指向 UC-09；转班作为管理学生中的独立目标，不改变功能。
4. **Should 项**：保留在类图中，不因工期假设删除；如实现阶段调整，按设计变更流程记录。
