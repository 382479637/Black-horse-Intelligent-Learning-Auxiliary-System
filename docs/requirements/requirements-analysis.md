## 1. 项目概述

### 1.1 背景与定位

“黑马智能学习辅助系统”是一个面向小型教学机构的教务与学习状态管理原型。系统以部门、教师、班级、学生、课程、成绩为主线，形成：

```text
组织架构 → 教学组织 → 学习数据 → 统计分析 → 学习预警
```

系统在功能规划上参考黑马程序员 Tlias 智能学习辅助系统的模块划分与业务流程，但**不复制其源代码、前端结构或配置文件**。所有 Java 类、数据模型、CUI 交互与持久化实现均需独立设计，并在 AI Usage Log 中记录 GenAI 的参与范围。

### 1.2 项目目标

1. 提供一个可完整运行的 Java CUI 应用，覆盖教务管理与学习状态分析的核心闭环。
2. 通过合理的分层、接口抽象与 SOLID 实践，展示可维护的面向对象设计。
3. 用可解释的规则引擎实现“学习预警”，在不接入外部 AI 服务的前提下体现“智能”价值。
4. 完成作业要求的文档与演示材料：需求、两轮设计、AI Usage Log 与演示视频。

### 1.3 “智能”的定义与边界

本项目的“智能”指：

- 基于学习成绩自动计算班级/学生指标；
- 按明确规则生成分级学习预警；
- 输出触发规则，使结果可解释、可复核。

本项目**不包含**真实大模型、机器学习、聊天机器人或自动推荐。“智能”能力限定为基于成绩数据的、可解释的规则计算。

### 1.4 参考系统的借鉴边界

| 借鉴内容 | 不借鉴内容 |
|---|---|
| 部门/员工/班级/学生的管理流程 | Tlias 的源代码、前端页面、接口实现 |
| 登录、分页查询、条件筛选的交互思路 | JWT、Spring Boot、MyBatis、Vue 等技术栈 |
| “教务管理 + 数据统计”的产品结构 | 其数据库表结构与后端分层实现 |

> 作业将“下载开源项目并修改”明确列为抄袭。因此，本项目只保留功能层面的启发，实现必须独立完成。

## 2. 利益相关者与角色

| 角色 | 说明 | 主要目标 | 系统 actor |
|---|---|---|---|
| 管理员（ADMIN） | 教学机构管理者 | 维护组织、人员、教学与课程数据；查看全局统计与预警 | 是 |
| 教师（TEACHER） | 任课教师，可能同时担任班主任 | 查看自己教学的班级与学生；录入自己任课课程的成绩；查看相关统计与预警 | 是 |
| 课程评审者 | 教师/助教/评分者 | 能构建、运行、演示并核对系统行为 | 否（利益相关者） |
| 项目开发者 | 学生本人/小组 | 完成需求、设计、实现、文档与视频 | 否（利益相关者） |

**角色简化：**

- 不设学生登录端。
- 不区分教务管理员、院系管理员等细粒度角色。
- 教师的权限范围由“教学任务（ClassCourse）”决定，而不是班主任身份。
- 用例图与权限模型只使用 `ADMIN`、`TEACHER` 两个系统 actor；评审者与开发者不参与系统操作。

## 3. 核心功能需求

### 3.1 功能总览

| 编号 | 模块 | 模块优先级 | 说明 |
|---|---|---|---|
| FR-AUTH | 登录与账户 | Must | 登录、登出、修改密码、角色菜单 |
| FR-DEPT | 部门管理 | Must | 部门 CRUD 与员工数展示；搜索为 Should |
| FR-EMP | 员工（教师）管理 | Must | 员工 CRUD、启停；重置密码为 Should |
| FR-COURSE | 课程管理 | Must | 课程 CRUD |
| FR-CLASS | 班级管理 | Must | 班级 CRUD、班主任、容量、状态；筛选为 Should |
| FR-TEACH | 教学任务管理 | Must | 班级课程与任课教师分配 |
| FR-STU | 学生管理 | Must | 学生 CRUD、转班、状态 |
| FR-SCORE | 成绩管理 | Must | 成绩录入、修改、删除、查询；批量录入为 Should |
| FR-STAT | 统计分析 | Must | 班级/学生统计与排名 |
| FR-WARN | 学习预警 | Must | 规则驱动的学生/班级预警 |
| FR-SYS | 系统与持久化 | Must | 初始化、加载、保存、异常恢复 |

**优先级定义：**

- `Must`：最终交付必须实现，并通过对应验收场景。
- `Should`：核心闭环稳定后实现；若时间不足可以不实现，**不阻塞 Must 验收**，但必须在报告或视频中说明未实现项及原因。未实现时对应菜单入口不显示。
- 本文档不设 `Could`；未列入本文档且不在 7.1 范围内的功能均视为范围外（见 7.2）。

**交付分层（用于控制实现风险）：**

| 层级 | 内容 |
|---|---|
| Must 核心闭环 | 登录与权限、部门/员工/课程、班级/教学任务/学生、成绩、统计、预警、班级状态与结业归档、File I/O 持久化 |
| Should 可选增强 | 成绩批量录入（FR-SCORE-06）、部门与班级多条件筛选（FR-DEPT-02、FR-CLASS-01）、管理员重置员工密码（FR-EMP-07） |
| 范围外 | 见第 7.2 节 |

模块整体的 `Must` 表示该模块至少包含必须实现的核心条目；具体条目的 `Must/Should` 以各 FR 行标注为准。Should 项在追溯表中单独标注，不计入 Must 验收覆盖。

### 3.2 FR-AUTH 登录与账户

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-AUTH-01 | 用户可使用用户名和密码登录 | 正确凭据进入对应角色主菜单 |
| FR-AUTH-02 | 用户名不存在或密码错误时统一提示 | 提示“用户名或密码错误”，不泄露账号是否存在 |
| FR-AUTH-03 | 被禁用的账号不能登录 | 提示“账号已被禁用，请联系管理员” |
| FR-AUTH-04 | 用户可登出并返回登录界面 | 登出后不能继续执行任何业务操作 |
| FR-AUTH-05 | 用户可修改自己的密码 | 需验证旧密码；新密码 ≥ 6 位；新旧不能相同；二次确认 |
| FR-AUTH-06 | 菜单按角色动态生成 | 管理员/教师只看到自己有权使用的入口 |
| FR-AUTH-07 | Service 层再次校验权限 | 即使绕过菜单，也不能越权读写数据 |
| FR-AUTH-08 | 密码不得明文存储或回显 | 数据文件中无明文密码；输入密码不回显 |
| FR-AUTH-09 | 登录失败不锁定账号 | 连续失败仅重复提示；本版本不做锁定（范围外） |

### 3.4 FR-EMP 员工（教师）管理

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-EMP-01 | 分页查看员工列表 | 默认每页 10 条；显示用户名、姓名、部门、角色、状态、入职日期 |
| FR-EMP-02 | 按姓名、部门、角色、状态筛选 | 条件可组合；无结果显示空状态 |
| FR-EMP-03 | 新增员工 | 用户名唯一；姓名、部门必填；角色为 ADMIN/TEACHER；初始密码符合规则；初始状态 `ACTIVE` |
| FR-EMP-04 | 修改员工资料 | 可改姓名、性别、手机号、邮箱、部门、用户名、角色；用户名唯一；部门必须存在；不得修改 `status`，状态只走 FR-EMP-06；字段范围见 4.6 |
| FR-EMP-05 | 删除员工 | 是班主任或任课教师时拒绝；不能删除自己；不能删除最后一个启用管理员 |
| FR-EMP-06 | 启用/禁用员工 | 禁用后立即无法登录；不能禁用最后一个启用管理员；仍是班主任或任一 ClassCourse 的任课教师时拒绝禁用，需先改派 |
| FR-EMP-07 | 重置员工密码（Should） | 管理员输入新密码；新密码 ≥ 6 位；重置后提示管理员转告用户尽快修改 |
| FR-EMP-08 | 教师查看本人资料 | 教师只能查看自己的资料，不能修改角色/状态 |
| FR-EMP-09 | 修改员工角色 | 仍是班主任或任课教师时，不得改为 `ADMIN`；不得将最后一个启用管理员改为 `TEACHER`；必须先改派或另设管理员 |
| FR-EMP-10 | 手机号/邮箱校验 | 手机号选填；填写时需符合格式；邮箱选填，格式基本校验 |

**员工状态规则：**

- `ACTIVE`：可登录、可被分配教学任务。
- `DISABLED`：不可登录；不能被新分配教学任务。
- 禁用/删除仍有教学任务的教师：拒绝，并列出其班主任班级与 ClassCourse，要求先改派；避免留下无法登录却仍占用任务的账号。
- 教师被禁用后，已有成绩仍保留；管理员可继续查看和维护这些成绩。

### 3.6 FR-CLASS 班级管理

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-CLASS-01 | 查看/筛选班级（Should） | 按名称、编号、状态、班主任筛选 |
| FR-CLASS-02 | 新增班级 | 编号唯一；容量 > 0；开始日期 ≤ 结束日期；初始状态 `PLANNED` |
| FR-CLASS-03 | 修改班级 | 可改编号、名称、班主任、起止日期、容量；容量不得低于当前在班人数；状态见 FR-CLASS-07 |
| FR-CLASS-04 | 指定/更换班主任 | 必须是 `ACTIVE` 的 `TEACHER`；班主任仅用于展示，不授予权限 |
| FR-CLASS-05 | 删除班级 | 仅非 `FINISHED` 班级可删除；仍有学生，或任一教学任务已有成绩时拒绝；无学生且无成绩时级联删除其教学任务 |
| FR-CLASS-06 | 查看班级详情 | 显示班级信息、容量/在班人数、所配课程与任课教师 |
| FR-CLASS-07 | 班级状态 | 仅管理员可转换；`PLANNED → ACTIVE → FINISHED`；不允许逆向转换；状态不随日期自动变化；`FINISHED` 为结业归档终态，班级及其教学任务、学生保留，班级与归档学生不得删除，成绩录入/更正按 FR-SCORE-02/03、删除按 FR-SCORE-04 执行；`FINISHED` 禁止新增学生、转入/转出、增删教学任务，但允许改派任课教师、更换班主任，以及录入/更正成绩；取消未开班班级走“转出学生 → 删除班级”，不设 `PLANNED → FINISHED` |
| FR-CLASS-08 | 容量约束 | 新增或转入学生时，在班人数不得超过容量 |

### 3.7 FR-TEACH 教学任务管理

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-TEACH-01 | 查看某班级的课程与任课教师 | 显示课程编号、课程名、任课教师、已录成绩数；未分配教师显示“待分配” |
| FR-TEACH-02 | 为班级添加课程 | 课程必须存在；同一班级同一课程只能有一条记录；新记录可暂不分配教师（待分配） |
| FR-TEACH-03 | 分配/更换任课教师 | 教师必须是 `ACTIVE` 的 `TEACHER`；待分配任务必须先分配教师才能录入新成绩；更换时保留已有成绩，统计与权限归当前任课教师 |
| FR-TEACH-04 | 移除班级课程 | 该班级课程已有成绩时拒绝 |
| FR-TEACH-05 | 教师查看自己的教学任务 | 只显示 `teacherId` 为自己的记录；待分配任务不对教师展示 |
| FR-TEACH-06 | 删除/禁用员工时的引用检查 | 员工仍是任一班级课程的任课教师时拒绝删除或禁用 |
| FR-TEACH-07 | 删除班级时的级联 | 班级无学生且无成绩时，删除班级同时删除其教学任务 |

**唯一约束：** `(classId, courseId)` 唯一，即一个班级的一门课程只有一条教学任务；`teacherId` 允许为空（待分配），但最多一位任课教师。

### 3.8 FR-STU 学生管理

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-STU-01 | 分页查看学生列表 | 显示学号、姓名、性别、班级、状态、入学日期 |
| FR-STU-02 | 按姓名、学号、班级、状态筛选 | 支持组合条件；空结果有提示 |
| FR-STU-03 | 新增学生 | 学号唯一；姓名与入学日期必填；班级存在；班级未满；`FINISHED` 班级不可新增；初始状态 `ACTIVE` |
| FR-STU-04 | 修改学生资料 | 可改姓名、性别、手机号；学号与入学日期创建后不可修改；`status` 只走 FR-STU-07；转班走 FR-STU-05 |
| FR-STU-05 | 学生转班 | 学生当前状态必须是 `ACTIVE`；当前班级不得为 `FINISHED`；目标班级状态必须是 `PLANNED` 或 `ACTIVE`，且存在、未满；日期仅展示，不作为转入条件；已有成绩保留在原班级/教学任务下，不迁移到新班级；新班级无需开齐旧课程；同一课程已有成绩时不在新班级重复建分 |
| FR-STU-06 | 删除学生 | 二次确认；确认后级联删除其成绩记录；当前在 `FINISHED` 班级，或在任一 `FINISHED` 班级的 ClassCourse 下有成绩的学生不得删除 |
| FR-STU-07 | 修改学生状态 | 仅管理员；`ACTIVE` / `SUSPENDED` / `GRADUATED`；状态用于展示与筛选，不自动删除数据，不改变已有成绩的班级归属；`SUSPENDED`/`GRADUATED` 不参与转班，需先恢复 `ACTIVE`；`FINISHED` 班级学生只能保持原状态或改为 `GRADUATED`，不得改为 `ACTIVE` |
| FR-STU-08 | 教师查看学生 | 教师只能查看自己任课班级的学生 |
| FR-STU-09 | 班级容量 | 见 FR-CLASS-08 |

### 3.9 FR-SCORE 成绩管理

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-SCORE-01 | 按班级/课程/学生查询成绩 | 可组合筛选；分页展示；班级归属按成绩所属 ClassCourse，而非学生当前班级 |
| FR-SCORE-02 | 录入或修改成绩 | 分数为 0–100 的数值，0 分为合法成绩；同一学生同一课程只能有一条记录 |
| FR-SCORE-03 | 业务校验 | 新录入：学生当前属于该班级、课程已配置、ClassCourse 已有任课教师、班级状态为 `ACTIVE` 或 `FINISHED`；修改/删除已有成绩不受学生当前班级限制 |
| FR-SCORE-04 | 删除成绩 | 二次确认；删除后统计与预警即时更新 |
| FR-SCORE-05 | 教师权限 | 教师只能查看/录入/修改/删除自己任课 ClassCourse 的成绩；待分配任务仅管理员可处理 |
| FR-SCORE-06 | 批量录入（Should） | 按班级-课程列出学生；输入“学号 分数”，分数可为 0；空行结束；单独输入 0 返回；非法行提示后继续，不中断整批 |
| FR-SCORE-07 | 修改时间 | 记录并展示 `updatedAt` |
| FR-SCORE-08 | 管理员权限 | 管理员可操作所有班级-课程的成绩 |
| FR-SCORE-09 | 成绩归属 | 每条成绩绑定不可变的 `classCourseId`；转班或更换教师不改变历史成绩的班级归属 |

**成绩录入规则：**

- 分数接受整数或小数；存储为 `double`；范围 `[0, 100]`；0 分有效。
- 学生不存在、当前班级不匹配、课程未配置、ClassCourse 无任课教师时拒绝新录入；历史成绩更正除外。
- 已有成绩时执行更新，不新增重复记录。
- 数据字段中的 `0` 按数值处理；取消当前录入使用空行，不使用 `0`。

### 3.10 FR-STAT 统计分析

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-STAT-01 | 班级统计 | 学生数、已录成绩数、平均分、及格率、最高分、最低分；聚合口径见 3.10.1 |
| FR-STAT-02 | 班级课程明细 | 每门课程的任课教师、平均分、及格率、最高分、最低分；待分配任务的任课教师显示“待分配”，成绩项显示“数据不足” |
| FR-STAT-03 | 班级学生排名 | 只列当前在班且在本班 ClassCourse 下有成绩的学生，按其在**本班 ClassCourse** 下的成绩计算；平均分降序，平均分相同按学号升序；展示排名、学号、姓名、平均分、不及格门数；在本班无成绩的学生不参与排名 |
| FR-STAT-04 | 学生统计 | 平均分、不及格门数、当前班级排名、课程成绩明细；平均分与明细统计该生全部成绩，可跨班级；排名按当前班级口径；可见范围完全无成绩时整体显示“数据不足”，有成绩但本班无成绩时排名显示“无排名（本班暂无成绩）” |
| FR-STAT-05 | 无成绩处理 | 按请求者可见范围判断：管理员看全部成绩，教师只看本人任课 ClassCourse；可见范围内无成绩显示“数据不足”；有成绩但本班无成绩时排名显示“无排名（本班暂无成绩）”；班级无成绩时统计项显示“数据不足” |
| FR-STAT-06 | 教师范围 | 教师只能查看自己任课 ClassCourse 的统计；聚合口径同班级聚合，排名只列当前在班且在本班本人任课 ClassCourse 下有成绩的学生；所有统计仅基于本人任课课程 |
| FR-STAT-07 | 计算口径 | 平均分为已有成绩的算术平均；及格为分数 ≥ 60；及格率 = 及格成绩数 / 已录成绩数；口径见 3.10.1 |

#### 3.10.1 统计口径

- 班级聚合统计：学生数按当前在班学生统计；已录成绩数、平均分、及格率等统计该班所有 ClassCourse 下的全部成绩；学生转班不改变原班级已产生的聚合结果，也不把旧成绩带入新班级。
- 班级学生排名：只列当前在班且在本班 ClassCourse 下有成绩的学生；每名学生只取本班 ClassCourse 下的成绩；在本班无成绩的学生不参与排名。
- 学生统计的“当前班级排名”：仅当该生当前在班、且请求者可见范围内有该生在本班 ClassCourse 下的成绩时参与排名；该生有成绩但本班无成绩 → “无排名（本班暂无成绩）”；可见范围完全无成绩 → “数据不足”。排名与预警使用同一“数据不足”口径。
- 学生统计（管理员）：统计该生全部成绩，可跨班级；课程明细按 ClassCourse 展示所属班级。
- 学生统计（教师）：只统计本人任课 ClassCourse 内该生的成绩；课程明细只列本人课程。
- 教师统计：限本人任课 ClassCourse；聚合口径与班级聚合一致；排名只列当前在班且在本班本人任课 ClassCourse 下有成绩的学生。
- 所有比例保留 1 位小数；“数据不足”按请求者可见范围判断：管理员看全部成绩，教师只看本人任课 ClassCourse。

### 3.11 FR-WARN 学习预警

| 编号 | 需求 | 验收要点 |
|---|---|---|
| FR-WARN-01 | 生成学生预警等级 | 按第 3.11.1 节规则计算，输出等级与命中规则 |
| FR-WARN-02 | 生成班级预警 | 班级及格率 < 60% 或平均分 < 60 时标记“需关注”；班级可见范围内无成绩显示“数据不足”；聚合口径见 3.10.1 |
| FR-WARN-03 | 按班级/等级筛选 | 无结果给出提示 |
| FR-WARN-04 | 教师范围 | 教师只能查看当前在自己任课班级中的学生预警；预警仅基于本人任课 ClassCourse 的成绩计算 |
| FR-WARN-05 | 数据不足 | 按请求者可见范围判断：管理员看全部成绩，教师只看本人任课 ClassCourse；可见范围内无成绩时显示“数据不足”，不参与等级比较与平均分排名 |
| FR-WARN-06 | 可解释性 | 每条预警必须展示触发的具体规则，不能只给等级 |
| FR-WARN-07 | 实时计算 | 预警不单独持久化，读取时按当前成绩计算 |

#### 3.11.1 学生预警规则

**判定流程：**

1. 先按请求者可见范围收集成绩：管理员取全部成绩，教师只取本人任课 ClassCourse 的成绩。
2. 可见范围内没有任何成绩 → 判定为“数据不足”，结束；不参与等级比较。
3. 否则评估下表全部适用条件，收集所有命中规则（不提前停止）。
4. 最终等级取所有命中规则中的最高等级；界面展示全部命中规则。
5. 若没有任何规则命中且存在成绩 → “正常”。

| 等级 | 规则编号 | 条件 |
|---|---|---|
| 重度 | R1 | 不及格课程数 ≥ 3 |
| 重度 | R2 | 平均分 < 50 |
| 中度 | R3 | 不及格课程数 = 2 |
| 中度 | R4 | 平均分 < 60 |
| 轻度 | R5 | 不及格课程数 = 1 |
| 轻度 | R6 | 平均分 < 65 |
| 正常 | — | 有成绩且 R1–R6 均未命中 |
| 数据不足 | — | 可见范围内无任何成绩 |

说明：

- “不及格课程数”按可见范围内已有成绩中分数 < 60 的课程数统计。
- “平均分”为可见范围内已有成绩的算术平均。
- 规则是累积的：例如平均分 52.3 会同时命中 R4 与 R6；界面必须把命中的 R4、R6 都列出，等级取最高。
- “数据不足”是独立判定，不参与等级比较；教师可见范围内无成绩、但管理员可见范围内有成绩时，两者结果可以不同。
- 教师查看时，“不及格课程数”和“平均分”仅统计本人任课课程；管理员查看全部课程。

## 4. 业务规则与引用完整性

### 4.1 唯一性约束

| 实体 | 唯一字段/组合 |
|---|---|
| Department | `name` |
| Employee | `username` |
| Course | `code` |
| Class | `code` |
| Student | `studentNo` |
| ClassCourse | `(classId, courseId)` |
| Score | `(studentId, courseId)`（`courseId` 经 ClassCourse 解析） |

### 4.2 引用完整性

| 操作 | 规则 |
|---|---|
| 删除部门 | 仍有员工 → 拒绝 |
| 删除员工 | 是班主任或任一 ClassCourse 的任课教师 → 拒绝；删除自己 → 拒绝；最后一个启用管理员 → 拒绝 |
| 禁用员工 | 是班主任或任一 ClassCourse 的任课教师 → 拒绝，要求先改派；最后一个启用管理员 → 拒绝 |
| 删除班级 | `FINISHED` 班级 → 一律拒绝；非 `FINISHED` 班级仍有学生，或任一 ClassCourse 已有成绩 → 拒绝；无学生且无成绩 → 级联删除 ClassCourse |
| 删除课程 | 被 ClassCourse 或 Score 引用 → 拒绝 |
| 删除学生 | 二次确认后级联删除其 Score；当前在 `FINISHED` 班级，或在任一 `FINISHED` 班级的 ClassCourse 下有成绩 → 拒绝 |
| 删除成绩 | 直接删除，二次确认 |
| 删除班级课程 | 该 ClassCourse 已有成绩 → 拒绝 |
| 更换任课教师 | 保留已有成绩；统计与权限归当前任课教师，不追溯历史教师归属 |
| 学生转班 | 学生当前状态必须为 `ACTIVE`；当前班级不得为 `FINISHED`；目标班级状态必须为 `PLANNED` 或 `ACTIVE`，且存在、未满；日期仅展示，不作为转入条件；旧成绩保留在原 ClassCourse，不迁移、不重复计入新班级；新班级无需开齐旧课程；同一课程已有成绩时不重复建分 |
| 成绩归属 | `Score.classCourseId` 创建后不可变；班级归属由 `ClassCourse.classId` 决定，不按学生当前班级推导 |
| 班级容量 | 新增/转入后不得超过 capacity；修改容量不得低于当前人数 |
| 任课教师 | 必须是 `ACTIVE` 的 `TEACHER`；ClassCourse 可暂为“待分配”，此时不得录入新成绩 |
| 角色变更 | 是班主任或任一 ClassCourse 的任课教师时，不得改为 `ADMIN`；最后一个启用管理员不得改为 `TEACHER`；必须先改派或另设管理员 |
| 班主任 | 必须是 `ACTIVE` 的 `TEACHER`；仅展示，不授予权限 |
| 班级状态 | 见 4.3；`FINISHED` 班级仍可改派任课教师、更换班主任，以及录入/更正成绩 |
| 在班人数 | 统计所有已分配学生，不论状态 |

### 4.3 状态规则

| 实体 | 状态 | 转换与操作者 | 影响 |
|---|---|---|---|
| Employee | ACTIVE / DISABLED | 仅 ADMIN；`ACTIVE ↔ DISABLED`；是班主任或任一 ClassCourse 任课教师时不得禁用；最后一个启用管理员不得禁用 | DISABLED 不能登录、不能被新分配教学任务 |
| Class | PLANNED / ACTIVE / FINISHED | 仅 ADMIN；`PLANNED → ACTIVE → FINISHED`；不允许逆向 | 见下方班级状态规则 |
| Student | ACTIVE / SUSPENDED / GRADUATED | 仅 ADMIN；用于展示与筛选；`SUSPENDED`/`GRADUATED` 不参与转班 | 不自动删除成绩，不改变已有成绩归属 |

**班级状态规则：**

- 状态由管理员手工维护，不根据开始/结束日期自动变化；日期仅作展示。
- `PLANNED`：可配置课程、分配教师、新增学生、接收转入学生；不得录入成绩。
- `ACTIVE`：可进行全部教学、学生与成绩操作；需要终止教学时转为 `FINISHED`，已有成绩的班级不得删除。
- `FINISHED`：结业归档终态；不得新增学生、转入/转出、增删教学任务；允许改派任课教师、更换班主任，以及录入/更正成绩。班级、教学任务与学生保留，不提供批量结业、清空或“删除归档”操作；`FINISHED` 班级不得删除。成绩按 FR-SCORE-02/03/04 维护，不因删除学生而级联删除。
- `FINISHED` 班级中的学生不得删除；任一学生在 `FINISHED` 班级的 ClassCourse 下有成绩时，也不得删除该学生，避免级联删除历史成绩。学生状态可保持原状态或改为 `GRADUATED`，但不得改为 `ACTIVE`，班级归属不变。
- `FINISHED` 班级不提供学生转出；如确需继续学业，属于范围外，需另行设计复学/重新编班流程。
- 取消未开班班级：先将学生转出（目标为 `PLANNED` 或 `ACTIVE`），再删除班级；不设 `PLANNED → FINISHED`，避免“从未开课却可补录成绩”的状态歧义。
- 非法转换（如 `FINISHED → ACTIVE`）必须拒绝并给出原因。

## 5. 数据模型

### 5.1 实体

| 实体 | 字段 | 说明 |
|---|---|---|
| Department | id, name, description | 部门 |
| Employee | id, username, passwordHash, passwordSalt, name, gender, phone, email, departmentId, role, status, hireDate | 员工/教师，同时是登录账号 |
| Course | id, code, name, description | 课程目录 |
| Class | id, code, name, headTeacherId, startDate, endDate, capacity, status | 班级 |
| ClassCourse | id, classId, courseId, teacherId, createdAt | 班级课程 + 任课教师（关联实体）；teacherId 可空=待分配 |
| Student | id, studentNo, name, gender, phone, classId, enrollmentDate, status | 学生；classId 为当前班级 |
| Score | id, studentId, classCourseId, score, updatedAt | 成绩；班级与课程经 ClassCourse 解析 |

### 5.2 关系

```text
Department   1 ────── * Employee
Class        0..* ──── 0..1 Employee      （headTeacherId：一个班级可有零或一位班主任）
ClassCourse  0..* ──── 0..1 Employee      （teacherId：一项任务可有零或一位教师）
Class        1 ────── * ClassCourse
ClassCourse  * ────── 1 Course
Class        1 ────── * Student           （当前班级）
Student      1 ────── * Score
Score        * ────── 1 ClassCourse
```

- 关系图左侧数字是左实体的多重性，右侧数字是右实体的多重性。例如 `ClassCourse 0..* ──── 0..1 Employee` 表示：一项教学任务可有零或一位教师；一位教师可承担零至多项教学任务。`Class 0..* ──── 0..1 Employee` 同理：一个班级可有零或一位班主任；一位教师可担任零至多个班级的班主任。
- `Score` 不直接持有 `classId`/`courseId`，二者通过 `ClassCourse` 解析。
- `ClassCourse.classId`、`ClassCourse.courseId`、`Score.classCourseId` 创建后不可变。
- 学生转班只改变 `Student.classId`，不改变已有 `Score.classCourseId`。

### 5.3 持久化文件

```text
data/
  departments.csv
  employees.csv
  courses.csv
  classes.csv
  class_courses.csv
  students.csv
  scores.csv
```

- 每行一条记录，首行为表头。
- 字段使用 UTF-8；CSV 特殊字符按引号转义。
- `passwordSalt` 与 `passwordHash` 分列存储，禁止明文密码；格式见 8.1。
- `class_courses.csv` 的 `teacherId` 留空表示“待分配”。
- `scores.csv` 字段为 `id,studentId,classCourseId,score,updatedAt`，不含 `classId`/`courseId`。
- ID 为内部 `long`；加载时按各文件最大 ID 恢复自增，删除后不复用。
- 加载顺序与无效行处理见 FR-SYS-06/11；诊断写入 `data/load-errors.log`。该文件是诊断文件，不属于 7 个核心数据文件，不参与加载；每次启动覆盖。
- 对用户的展示优先使用业务编号（学号、课程编号、班级编号、用户名）。

#### 5.4.1 初始化与修复场景

术语：

- **核心文件**：`departments.csv`、`employees.csv`、`courses.csv`、`classes.csv`、`class_courses.csv`、`students.csv`、`scores.csv`。
- **空文件**：不存在、0 字节，或只有表头。
- **有数据**：至少存在一条可解析记录。
- **可用管理员**：`role = ADMIN` 且 `status = ACTIVE` 的员工。

| 场景 | 判定 | 行为 |
|---|---|---|
| 全新初始化 | `data/` 不存在，或 7 个核心文件全部为空/缺失 | 创建全部文件，写入 5.4 演示数据；种子班级直接写为 `ACTIVE` |
| 部分初始化 / 正常加载 | 至少一个核心文件有数据（无论是否有文件缺失） | 只为缺失/空文件创建表头；**不写入任何演示业务数据**；加载已有数据并按 FR-SYS-06 处理坏行；执行管理员兜底 |
| 管理员兜底 | 加载后没有可用管理员 | 按下方规则创建默认管理员；不写入其它演示数据 |
| 坏行/坏引用 | 解析失败、重复 ID/业务键、非空外键缺失；可空外键缺失 | 按 FR-SYS-06：坏行与非空外键缺失行跳过并记录；可空外键置空并记录；不触发重新初始化；不覆盖原文件 |

**管理员兜底规则：**

1. 部门：优先复用名称为“教务部”的部门；不存在则追加一条，`id` 取当前最大部门 `id + 1`。
2. 用户名：优先 `admin`；若该用户名已存在（无论状态或角色），依次尝试 `admin2`、`admin3`……直到唯一。
3. 新账号固定为：密码 `Admin@123`、姓名“系统管理员”、`role = ADMIN`、`status = ACTIVE`、部门为第 1 步确定的部门。
4. **不修改任何已有员工记录**，包括不重新启用已禁用的 `admin`，也不改变已有账号的角色。
5. 控制台输出实际创建的用户名、原因；同时按 FR-SYS-12 写入 `data/load-errors.log`（每次启动覆盖并脱敏）。
6. 若员工文件无法解析且无法安全追加，明确报错并安全退出，不静默继续。

**部分初始化的边界：**

- 已有文件一律不覆盖、不重写、不补演示数据。
- 缺失文件只写表头，保证后续可读。
- 已有员工引用了不存在的部门时，该员工行按坏引用跳过并记录；管理员兜底仍会创建可用管理员。
- 可空外键引用缺失时置空并记录，不跳过整行：`Class.headTeacherId` 置空表示无班主任，`ClassCourse.teacherId` 置空表示待分配；非空外键缺失才跳过整行。
- 初始化只发生在启动加载阶段；运行期间删除文件不会立即重建，重启后按本矩阵处理。

### 7.1 范围内

- 管理员/教师两种角色与登录、登出、修改密码。

- 分层 CUI、输入校验、引用完整性、搜索与分页。

### 7.2 范围外

- GUI、Derby、JUnit、强制 Git（阶段 2 内容）
- 真实 AI/LLM、聊天机器人、自动推荐
- 考勤、作业、考试安排、课表

- 多用户并发、网络部署、学生端登录
- 操作日志、数据备份/恢复界面
- 批量结业/归档操作（班级逐个转为 `FINISHED` 即为归档）
- 密码找回、邮件重置
- 国际化、主题、快捷键体系

### 7.3 规模与交付假设

- 目标团队为 1–2 人；Must 范围按课程项目周期内的演示规模控制，预计约 30–40 个 Java 类（实体、仓储、服务、CUI 与工具类）。

- 若仍不足，可将部门/课程的“修改、删除”降为 Should（保留查看与新增），并在 3.1、对应 FR 行、AC 与追溯表中同步标注；不得只在报告或视频中口头降级。
- 范围取舍理由由学生本人在 Component 1.1 反思中说明；本文档只记录范围、优先级与降级预案，不代写该反思。

## 8. 约束与假设

### 8.1 约束

| 类别 | 约束 |
|---|---|
| 语言/构建 | Java 21（LTS）、Maven 3.9+、标准目录结构；`maven.compiler.release=21` |
| 界面 | 控制台 CUI，无 GUI |
| 持久化 | 仅 File I/O（CSV/文本） |
| 数据库 | Project 1 不使用数据库；Project 2 才要求 Apache Derby Embedded，届时替换 `persistence` 层实现 |
| 依赖 | 优先 JDK 标准库；不引入需手工配置的依赖 |
| 运行 | 单机、单进程、单用户；无需启动服务 |
| 数据规模 | ≤1,000 学生、≤100 班级、≤50 课程、≤20,000 条成绩 |
| 平台 | Windows / Linux / macOS，JDK 21+ |
| 数据位置 | 项目相对路径 `data/` |
| 初始化 | 全新初始化自动创建并写入演示数据；部分初始化只补文件与默认管理员，不注入演示数据 |
| 安全 | 输入不回显；加载日志每次启动覆盖，只记录文件名、行号、错误类别与安全摘要，不记录整行、密码、哈希、盐或联系方式 |
| 密码存储 | `PBKDF2WithHmacSHA256`；210,000 次迭代；16 字节 `SecureRandom` 盐；256 位派生密钥；salt/hash 以 Base64 分列存储；比较使用 `MessageDigest.isEqual` |
| 一致性 | 单文件原子替换 + 启动引用校验；不实现数据库级事务 |
| 编码 | 源码/数据 UTF-8；控制台使用终端字符集 |

### 8.2 假设

- 评分环境具备 JDK 21+ 与 Maven，可按标准命令构建运行。
- 本机同时装有 JDK 21 与 JDK 25；构建统一使用 JDK 21（Maven 当前已指向 21），源码不使用高于 21 的语言特性，确保在 JDK 21 上可编译。
- Project 1 不引入数据库依赖；持久化通过仓储接口隔离，Project 2 接入 Derby 时只替换实现。
- 使用者具备基本菜单操作能力。
- 演示数据为合成数据，不涉及真实个人信息。
- 7 个核心文件全部为空/缺失时视为全新初始化；只要任一核心文件有数据，就不注入演示数据，缺失文件按 5.4.1 补齐。
- 种子数据中的班级状态直接为 `ACTIVE`，不受“新建班级初始为 `PLANNED`”规则约束。
- 一个“班级-课程”组合最多一位任课教师；分配前允许处于“待分配”。
- 教师权限范围由 ClassCourse 决定；班主任仅用于展示。
- 更换任课教师后，统计与权限归当前任课教师，不保留历史教师归属。
- `Score` 绑定 `ClassCourse`；学生转班不迁移已有成绩。
- 班级状态由管理员手工维护，日期不自动改变状态；`FINISHED` 为结业归档终态，班级、学生与教学任务保留，成绩按 FR-SCORE-02/03/04 维护。
- 删除学生时级联删除其成绩，但 `FINISHED` 归档班级的学生及有 `FINISHED` 历史成绩的学生除外；其它删除遵循引用完整性。
- 系统时间为本机时区；日期格式 `yyyy-MM-dd`。
- 单次运行只有一个用户操作，不考虑并发写冲突。

| AC-20 | 干净环境构建运行 | 无需手工配置 |
| AC-21 | 新增部门、修改名称、重复名称 | 新增成功；修改生效；重复名称拒绝 |
| AC-22 | 新增员工、筛选员工、禁用无教学任务员工 | 员工可登录；筛选正确；禁用后登录失败 |
| AC-23 | 新增/修改/删除课程；删除被引用课程 | CRUD 正常；被引用时拒绝 |
| AC-24 | 新增/修改班级、`PLANNED → ACTIVE → FINISHED`、尝试 `FINISHED → ACTIVE` 与 `PLANNED → FINISHED`、删除有成绩的班级、取消未开班班级 | 班级 CRUD 正常；正向转换成功；非法转换拒绝并说明原因；有成绩时删除拒绝；转出全部学生后可删除空班级 |
| AC-25 | 添加班级课程但不分配教师；移除已有成绩的任务 | 显示“待分配”；新成绩录入被拒绝；分配教师后可录入；有成绩时移除拒绝 |
| AC-26 | 学生新增、转班、删除普通学生；转出后查看原班级与新班级统计 | CRUD 正常；原班级聚合统计不变、排名不含已转出学生；新班级统计不含旧成绩；删除级联成绩 |
| AC-27 | 录入 0 分；成绩输入处输入空行 | 0 分保存成功；空行取消当前录入 |
| AC-28 | 教师查看统计与预警；管理员查看同一班级 | 教师只统计本人任课 ClassCourse 的成绩，非任课班级不可见；管理员可见全部 |
| AC-29 | 预警边界：平均分 59/60、64/65；单科 59/60 对不及格门数的影响 | 等级按规则正确，展示命中规则 |
| AC-30 | CSV 重复 ID、缺失外键、损坏行 | 跳过并记录；系统启动；生成加载诊断日志 |
| AC-31 | 检查密码存储 | CSV 无明文；salt/hash 为 PBKDF2 格式 |
| AC-32 | 管理员重置员工密码（Should） | 旧密码登录失败；新密码登录成功；重置成功后提示管理员转告用户尽快修改 |
| AC-33 | 部门按关键字、班级按名称/编号/状态/班主任筛选（Should） | 组合条件结果正确；空关键字返回全部；无结果显示空状态 |
| AC-34 | 成绩批量录入（Should） | `学号 分数` 逐条保存；0 分有效；空行结束；单独 0 返回；非法行提示后继续，不中断整批 |
| AC-35 | 向 `PLANNED` 班级录入成绩 | 拒绝并提示班级未开始；转为 `ACTIVE` 后可录入；`FINISHED` 班级仍可录入/更正成绩 |
| AC-36 | 教师查看某学生预警，该生只有其他教师课程的成绩 | 教师侧显示“数据不足”；管理员查看同一学生显示实际等级 |
| AC-37 | 禁用、删除、将最后一个启用管理员改为 `TEACHER` | 三种操作均拒绝；系统始终至少保留一个启用的 `ADMIN` |
| AC-38 | 通过“修改员工资料”尝试修改 `status` | 界面不提供该字段；Service 拒绝绕过调用；必须走启用/禁用流程 |
| AC-39 | 部分核心文件缺失/为空、已有数据但无可用管理员时启动 | 不写入演示业务数据；缺失文件创建表头；已有文件不被覆盖；创建可用默认管理员且其部门存在；坏引用跳过并记录 |
| AC-40 | 首次运行后检查种子数据 | 种子班级为 `ACTIVE`；待分配任务无成绩；不存在带成绩的 `PLANNED` 班级；所有种子成绩满足 4.3 |
| AC-41 | 转班目标班级/学生状态不满足 | 目标 `FINISHED`、学生 `SUSPENDED`/`GRADUATED`、目标满员均拒绝；目标 `PLANNED`/`ACTIVE` 且学生 `ACTIVE` 时成功；目标日期已过但状态为 `PLANNED` 仍允许 |
| AC-42 | 学生同时命中多条预警规则 | 展示全部命中规则；等级取最高；“数据不足”不参与等级比较 |
| AC-43 | 修改自己的密码 | 旧密码错误、新旧相同、新密码 < 6 位均拒绝；成功后旧密码失败、新密码成功 |
| AC-44 | 班级容量 | 新增或转入超过容量时拒绝；修改容量低于当前在班人数时拒绝 |
| AC-45 | 删除成绩 | 二次确认后删除；统计与预警即时更新；教师不能删除非本人任课课程的成绩 |
| AC-46 | 班级预警 | 及格率 < 60% 或平均分 < 60 显示“需关注”；班级无成绩显示“数据不足” |
| AC-47 | 删除 `FINISHED` 班级；删除 `FINISHED` 班级学生；删除在 `FINISHED` 班级有历史成绩的已转班学生；将 `FINISHED` 班级学生改为 `ACTIVE` | 三种删除与状态修改均拒绝；`FINISHED` 班级仍可查看、更正成绩；班级与学生保留，成绩不因删除学生而丢失 |
| AC-48 | 学生转班后查看其统计 | 平均分与课程明细包含原班级成绩；当前班级排名显示“无排名（本班暂无成绩）”；该生完全无成绩时显示“数据不足” |
| AC-49 | 已有旧 `load-errors.log`，本次启动包含坏行 | 旧日志被覆盖；新日志含时间戳、文件名、行号、错误类别；不含整行、密码、哈希、盐或联系方式 |
| AC-50 | 将 `load-errors.log` 设为只读（或目录不可写）后启动 | 控制台警告日志不可写；系统仍完成加载；不阻断启动 |

## 12. 待评审项与已知风险

以下不是未完成项，而是需要在评审中确认的设计决策：

| # | 事项 | 当前决定 | 风险/备选 |
|---|---|---|---|
| 1 | 教师统计/预警范围 | 统计与预警均只基于本人任课 ClassCourse 的成绩；改派后归当前教师；“数据不足”按请求者可见范围判断 | 口径统一；管理员可见全部课程；教师可能看到“数据不足”而管理员看到实际等级 |
| 2 | 删除学生 | 级联删除成绩；`FINISHED` 归档班级学生及有 `FINISHED` 历史成绩的学生禁止删除 | 普通学生误删不可恢复；归档学生只能改资料，不能删除或转出 |
| 3 | 班主任与任课教师并存 | 班主任仅展示，权限看 ClassCourse | 两个“教师-班级”关系可能让类图显得冗余 |
| 4 | 禁用仍有教学任务的教师 | 禁止禁用；要求先改派 | HR 流程多一步；避免失效任务 |
| 5 | 演示数据自动生成 | 仅全新初始化写入；种子班级为 `ACTIVE`；待分配任务无成绩 | 评审者可能误认为硬编码；需在 README/报告中说明 |
| 6 | 成绩批量录入 | Should；核心闭环使用单条录入 | 大数据量下效率一般，但演示足够 |
| 7 | CSV 持久化 | 每实体一个文件 | 未来迁移数据库需替换持久化层；当前通过接口隔离 |
| 8 | 控制台编码 | 使用终端字符集 | Windows 不同终端可能有差异；需启动时检测 |
| 9 | 学生状态 | 仅展示/筛选；不改变已有成绩归属 | 状态对业务影响有限，需在报告中说明 |
| 10 | 无操作日志 | 范围外 | 不影响评分要求，但审计能力弱 |
| 11 | 成绩历史归属 | `Score` 绑定不可变 `classCourseId`；转班不迁移 | 原班级聚合稳定；学生统计可跨班 |
| 12 | 班级状态 | 管理员手工转换；日期不自动推进；`PLANNED` 不得录成绩；`FINISHED` 为永久归档；取消未开班走转出+删除 | 需按 4.3 的转换表测试非法转换、`PLANNED` 录分与归档删除保护 |
| 13 | 待分配教学任务 | `teacherId` 可空；无教师不得录新成绩 | 增加空值分支；类图/代码需明确 |
| 14 | 跨文件一致性 | 单文件原子替换 + 启动引用校验 | 崩溃窗口仍可能存在；以诊断日志兜底 |
| 15 | Must/Should 优先级 | 4 条 Should 不阻塞 Must 验收；未实现时菜单不显示 | 需在报告/视频中说明未实现的 Should 项 |
| 16 | 初始化与修复矩阵 | 全新初始化写演示数据；部分初始化只补文件与管理员 | 场景组合较多，需按 5.4.1 逐项验证 |
| 17 | 同一学生同一课程唯一 | 转班后同课程不重复建分 | 新班级同课程无法再次评分；演示可接受，若需重修需扩展成绩模型 |
| 18 | `FINISHED` 班级归档 | 班级、学生、教学任务保留；不提供批量结业/清空；归档班级及归档学生不得删除；成绩按 FR-SCORE-02/03/04 维护 | 错误录入需在转 `FINISHED` 前纠正；归档后只能改资料/改成绩 |
| 19 | Must 范围规模 | 按 1–2 人、课程项目周期估算；Must 只保留闭环条目；工期不足按 7.3 降级并同步改文档 | 单人开发或工期缩短时需实际裁剪，不能只口头说明 |
| 20 | 学生统计排名 | 有成绩但本班无成绩显示“无排名（本班暂无成绩）”；完全无成绩显示“数据不足” | 两种文案需在统计与预警中保持一致 |
| 21 | 加载日志 | 每次启动覆盖；只记录文件/行号/错误类别/安全摘要；写入失败不阻断启动 | 日志失败时诊断信息只剩控制台；需在测试中覆盖 |
