## 仍需关注的问题

### 1. FINISHED 班级没有保留成绩的清理或归档路径

**程度：中**

FR-CLASS-07 与 4.3 规定 FINISHED 班级禁止转入和转出；FR-CLASS-05 又规定班级有学生时不得删除。需求没有定义毕业班的归档、批量结业或学生历史转出机制。当前唯一明确的清空方式是逐个删除学生，而 FR-STU-06 会级联删除成绩，可能造成历史数据损失。

如果系统的预期就是永久保留 FINISHED 班级及学生，可将此写成明确规则并说明不能删除；如果需要清理或归档，则应定义归档行为和成绩保留策略。不要让删除学生成为隐含的班级结业流程。

### 2. Must 核心范围仍然偏宽

**程度：中，取决于团队人数和实现时间**

优先级语义已经清楚，但核心闭环仍把部门、员工、课程、班级、教学任务、学生、成绩的广泛 CRUD、登录与双层权限、CSV 持久化与损坏恢复、统计排名和学生/班级预警全部列为 Must。文档没有说明选定的功能规模如何适配个人或两人团队。

建议按最终可演示的核心用例检查实施容量。若团队规模或工期有限，可再将非闭环管理操作降为 Should；若坚持全部 Must，则在 Component 1.1 反思中由学生本人说明范围为何可控及其取舍依据。

### 3. 学生统计可能没有“当前班级排名”

**程度：低**

FR-STAT-04 要求展示学生的“当前班级排名”；3.10.1 又规定排名只纳入当前班级且在本班 ClassCourse 下有成绩的学生。学生转班后若只保留原班成绩，则其全部成绩平均分可以计算，但在新班级没有可参与排名的成绩，排名字段应如何显示尚未说明。

建议明确这种情况显示“无排名/数据不足”，并确保学生统计界面与预警界面的数据不足文案口径一致。

### 4. 加载诊断文件的覆盖与失败策略未写明

**程度：低**

FR-SYS-12 指定把详细错误写入 `data/load-errors.log`，但未说明每次启动覆盖还是追加，也未说明该日志文件无法创建/写入时是否阻止加载。附录又要求日志不输出密码，因此建议明确日志只记录文件、行号、错误类别和安全摘要，不能记录整行或敏感字段。

建议规定每次启动新建/覆盖日志，并在日志写入失败时给出控制台警告、继续或安全退出的规则；无论哪种都不得输出密码、哈希或原始敏感行。

### 5. `ClassCourse` 关系图对 nullable `teacherId` 的多重性易被误读

**程度：低**

第 5.2 节写 `ClassCourse * ──── 0..1 Employee`，附注说明教师可空。图示方向与多重性容易让读者误认为每个 Employee 对应 ClassCourse 的数量是 0..1，而不是每个 ClassCourse 有 0..1 位教师。

建议把关系端点多重性分别标明，例如在 Employee 端标 `0..*`、ClassCourse 端标 `0..1`，或用文字明确“一项教学任务可有零或一位教师；一位教师可承担零至多项教学任务”。

## 建议修订顺序

1. 决定 FINISHED 班级是否永久保留；若可删除/归档，定义不丢成绩的路径。
2. 明确学生转班后在新班级无本班成绩时的排名显示。
3. 完善加载日志的覆盖、失败与脱敏规则。
4. 修正 ClassCourse—Employee 关系图的多重性表达。
5. 再结合团队规模确认 Must 核心范围是否能在工期内完整实现。
